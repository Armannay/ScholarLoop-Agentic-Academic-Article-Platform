# Step 12 — Frontend 10b: projects, runs, checkpoints and the article

**Step:** 12 — the "10b" half of the frontend work (New Project, Run view, Checkpoint
modal, Stop report, Article viewer, `.md` export), on top of the Step 10a shell.

**Depends on:** Step 10a (`frontend/` shell: auth, accounts, agents, status console,
mock server, typed-client seam, SSE reader — PR #17) and Step 10 (`docs/openapi/`, the
OpenAPI 3.1 spec and its typed client — PR #19), plus the read models the screens render:
Step 9b (runs, `RunView`, state machine, `StopReport`, SSE event log), Step 11
(`/api/projects`), Step 5 (article store: history, diff, snapshots, restore) and Step 8
(`Plan`, `QualityReport`).

**Contract changes:** **none.** No file under `backend/app/contracts/` is touched and
`make schemas-check` still passes; everything the new screens render already exists in
CONTRACTS v1. The gaps this step found are in the *surface* spec and in the policy file;
they are written up in `docs/arena-log/step-12/spec-change-requests.md` rather than edited
into `docs/openapi/`.

## What a user can now do

1. **New project** — a Brief form with inline validation that mirrors deterministic
   intake: required fields, BCP-47 language, 300..30,000 target words, ±15% tolerance
   shown live, contradictory `must_include`/`must_avoid` refused, each instruction capped
   at 40 words. A `409 needs_user_input` from the API is turned into the same inline
   questions, and focus moves to the first field that needs attention.
2. **Run view** — state badge (12-state vocabulary), a plan board that groups the
   Planner's tasks by the role that owns them (done/ready/blocked derived from the event
   log), the live change log over SSE with `?after=<seq>` resume and de-duplication,
   token / iteration / cost meters against the caps, and a Q-per-iteration chart with one
   chip per hard gate (plus a `<table>` twin for screen readers).
3. **Checkpoint modal** — Finish · Continue with extra budget · Edit goals · Roll back,
   rendered from `stop_report.options` so only legal decisions are offered. Tab is
   trapped, Escape closes, the first option is focused, and a `needs_input` checkpoint
   opens itself because the loop is blocked on the user.
4. **Stop report** — the reasons, Q series, best snapshot, iterations, token spend and
   estimated cost, the Planner's named risks, the failed gates and the raw
   `evidence` object.
5. **Article viewer** — sections with status/version/word count and open issues, a
   per-section version list, a unified diff, snapshot restore reported as *new versions*
   (never a rewrite), and `dir=rtl` + `lang` when the Brief language is `fa` or `ar`.
6. **Export `.md`** — front matter + sections + references + source cards, downloaded
   from `GET /article` so the file cannot disagree with the screen. DOCX/PDF are a
   visibly disabled "later" button, not a silently lossy converter.

Plus the project list with derived run facts and a project page that starts another run
from the project's own brief.

## Rules from the brief, and where they are enforced

| Rule | Where |
| --- | --- |
| typed API client generated from OpenAPI | `npm run client` → `src/generated/api-schema.d.ts` (git-ignored), regenerated by `prelint`/`pretest`; `src/types.ts` aliases the generated schemas |
| never render or store secrets; no `localStorage` beyond the session | JWT moved to `sessionStorage` (old `localStorage` key deleted on read); API keys were already write-only; no key material appears in any new component |
| loading, empty and error states | every panel: skeleton text, an explicit empty sentence, and an error with Retry (the SSE feed adds Reconnect) |
| keyboard accessible | modal focus trap + Escape + first-radio focus, labelled controls, `aria-invalid`/`aria-describedby` per field, focus to the first invalid control, real `<button>`/`<label>` everywhere, table twin for the chart |
| Vitest unit tests | 52 tests in 9 files (Brief validation, wizard, run view, checkpoint decision, stop report, article viewer, export, routing, app walk) |
| Playwright smoke test for the key flows | `frontend/e2e/smoke.spec.ts` (+ `playwright.config.ts` with the mock-API dev server); CI job added |
